# UE-007 — Sharpen menu text

- Status: done
- Owner: Vision (font/layout); Milu (evidence/docs/launch)
- Reviewer: Stark

User reports a blurry menu. The viewport is3440x1440, but Canvas currently scales
SmallFont glyphs by1.44 and uses fractional coordinates. Investigate the font
cache/rendering path; replace scaled cached glyphs with runtime font rendering
at appropriate integer pixel sizes and align text/buttons to pixels. Preserve
camera/FOV/cloud/Resume/Exit behavior, output resolution and scene rendering.

Acceptance: actual native-resolution before/after menu inspected; readable text
fits at1600x1000 and3440x1440; native input/hitbox regression tests pass; Stark
independently reviews sharpness and layout. Do not claim all blur was due to scene
resolution or that a screenshot downscaled for chat is a native-pixel comparison.

Baseline: `artifacts/ue007-before/menu-3440x1440.png` under unreal-prototype.

First replacement compiled and passed31 input/hitbox checks but rendered no text.
Actual native screenshot review rejected it. The Canvas FSlateFontInfo constructor
requires a backing UFont object: CanvasItem.cpp HasValidText rejects null Font,
even with a valid standalone composite. Evidence: `artifacts/ue007-text-missing.png`.
Vision supplied a persistent UPROPERTY Roboto UFont with runtime cache. The engine
UFont's composite takes precedence over explicit standalone composite settings;
do not attribute its output to unverified hinting/loading overrides. Fresh visual
validation is pending. World resolution/TSR settings were not changed.

Corrected UFont-backed runtime capture restores visible, substantially crisper
glyphs. Log confirms `/Engine/EngineFonts/Roboto.Roboto`, CacheType1 (Runtime).
Milu and Stark inspected the original-resolution3440 image. They found a slight
long-button label overflow; Vision reduced button nominal size16 to14 while
retaining label14/title28 sizes, all multiplied into integer font-size requests.
This yields labels/buttons20 and title40 font-size units at1440 height. Text draw
scale is1 and positions are rounded; geometry/hitboxes remain unchanged. Final
both-resolution fit and regression checks completed by Milu: all labels fit and
text is visibly sharper in original-resolution captures at 1600x1000 and
3440x1440. Both fresh runtime reports pass all 31 input/hitbox checks. These
exercise engine input dispatch, not physical OS mouse/focus behavior.

Final evidence: `artifacts/ue007-menu-1600x1000.png` and
`artifacts/ue007-menu-3440x1440.png`, UE 5.8.4, CockpitStudy map, Gripen cockpit,
vertical FOV 64.011 degrees, overcast menu capture. Scene resolution/TSR settings
were unchanged. Reopened native borderless fullscreen (PID 51196); process is
responsive and Play.log confirms 3440x1440wf. Stark independently inspected both
final images at original resolution and passed sharpness, contrast and fit:
Canopy Mount and Scattered have padding, with no overlap, clipping or overflow.
No further font tuning required. This fixes menu text, not world/cockpit textures.
