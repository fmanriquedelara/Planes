- Daylight palette, filmic tone mapping, distance haze, SSAO and 2x MSAA are explicit.
- Runtime review must check cockpit readability, natural horizon transitions,

- Provide comparable before/after evidence, or explicitly mark runtime review pending.

## Evidence and outcome
Implemented a source-level first pass:
- Shared pale blue horizon/ground-horizon/fog colour with a deeper blue zenith,
  neutral ground bounce and a narrower procedural sun halo.
- Slightly warm directional light at energy 1.2, sky ambient energy 0.85,
  filmic tone mapping with exposure unchanged at 1.0.
- Distance haze density 0.00008 with aerial perspective 0.5 and limited sky
  influence 0.15; no volumetric fog or new cloud assets.
- SSAO radius 0.5, intensity 0.65, power 1.2 for restrained contact shading.
- Project-wide 2x MSAA (`msaa_3d=1`) to address polygon-edge aliasing.

Baseline and edited settings target the existing Godot 4.1 Forward+ project and
`Flight.tscn`, with both existing cockpit and external cameras preserved.
No scripts, input bindings, transforms, camera properties, assets or dependencies
were changed. Runtime visual and performance validation remain pending: Milu
could not locate a Godot executable in the checked local locations. Values are
initial tuning choices, not a claim of achieved photorealism.

Godot 4.1 property names and enum values checked against primary documentation:
- [Environment](https://docs.godotengine.org/en/4.1/classes/class_environment.html)
- [ProceduralSkyMaterial](https://docs.godotengine.org/en/4.1/classes/class_proceduralskymaterial.html)

## Stark independent review — 2026-10-31

Verdict: source review passes; rendered acceptance remains unverified. Keep this
task in review until matching cockpit/external captures can be inspected. No

Inspected the actual git diff for both assigned files. Changes are confined to
sky/environment/light properties and project MSAA. Node transforms, scene
resources, cameras, scripts and inputs are preserved. The existing physical
camera attributes are unchanged; there is no newly enabled automatic exposure.

Checked property semantics against the Godot 4.1 primary documentation linked
above: ambient source 3 selects the sky, tone mapper 2 selects Filmic, and MSAA
value 1 requests 2x. Distance fog uses an exponential density; aerial perspective
blends its colour toward the sky, with the required sky background already set.
SSAO's direct-light influence remains at its default zero, avoiding artificial
occlusion darkening on directly lit surfaces.

Review notes and remaining checks:
- The sky is still a procedural gradient. This pass does not add physical
  atmospheric scattering, cloud depth, canopy reflections or cockpit detail.
- The reduced ambient energy plus Filmic mapping could darken cockpit controls.
  Inspect readability before accepting the visual result; settings alone do not
  establish the desired exposure balance.
- Check haze at actual scenery distances and flight altitude. The density is a
  conservative starting value, not evidence of a natural horizon transition.
- SSAO radius 0.5 must be judged against actual cockpit scale. Check for broad
  halos and screen-edge changes while looking around.
- 2x MSAA addresses polygon edges; it does not resolve texture/specular aliasing.
  Inspect thin cockpit edges and moving aircraft silhouettes at fixed resolution.
- SSAO, aerial perspective and MSAA incur rendering cost. No performance gain,
  frame-time budget or supported-hardware result has been measured.

Required rendered checks: matched before/after cockpit and external views with
camera, resolution, engine version and settings recorded; readable close cockpit
controls, retained sky highlights, gradual scenery fade and no heavy SSAO halos.
Record frame times on the same hardware/resolution before making cost claims.
The existing imported-airframe shader preservation issue remains separate work.
