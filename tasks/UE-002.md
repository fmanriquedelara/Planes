# UE-002 — Startup warnings, ultrawide and agent launch workflow

- Status: done
- Owner: Vision (rendering/camera), Milu (launcher/docs/evidence)
- Reviewer: Stark

## Scope

Fix the user's normal-game warnings about missing Lumen tracing data and sky
cached-lighting exposure. Add native 3440x1440 ultrawide/fullscreen and custom
resolution launch options. Persist the direct-game launch workflow for agents.

## Acceptance criteria

- Correct rendering prerequisites; do not suppress screen messages to hide issues.
- A warmed normal-game capture shows no reported Lumen/exposure warnings.
- Ultrawide fills the requested aspect, adds side view and preserves vertical
  cockpit framing without letterboxing or stretching.
- Standard and ultrawide launch/capture paths work; log version, camera and settings.
- Root AGENTS and team README point agents to reproducible launch instructions.
- Stark independently inspects actual rendered evidence.

## Evidence and outcome

User supplied a real game-view screenshot with Lumen missing-ray-data and cached
lighting exposure warnings. Previous MRQ-only validation did not expose those
messages. Milu read the primary monitor as 3440x1440. Vision owns source-backed
rendering settings and aspect changes; Milu owns the launcher and documentation.
Vision enabled software Lumen tracing with generated mesh distance fields.
`r.EyeAdaptation.CachedLightingPreExposure=8` covers EV [-4,16], preserving the
physical camera's EV13. This corrects the cached-lighting range rather than
changing camera exposure or hiding screen messages. PilotEye disables aspect
locking and overrides the axis constraint to Maintain Y FOV.

Milu added `-Ultrawide`, `-NativeResolution`, custom `-Width`/`-Height` and
borderless `-Fullscreen` Play options. GameCapture runs the normal renderer
offscreen and requests `Shot SHOWUI` after 180 deferred frames, then quits after
210. It verifies fresh output and PNG dimensions, saves per-resolution logs and
metadata. MRQ's fixed cinematic capture remains explicitly separate. GUI Play
and Editor launch through Start-Process; a false LASTEXITCODE error from the
original GUI call-operator path was corrected.
